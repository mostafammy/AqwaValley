# Irrigation AI — Frontend Integration Guide

This document is your complete guide to consuming the AI-powered Irrigation engine from the Next.js frontend using tRPC.

## 🧠 How the Logic Works (Simply Explained)
When the user clicks "Generate Plan" on the frontend, the backend doesn't just send a generic question to an AI. Here is what happens under the hood:
1. **Data Gathering**: The backend instantly gathers the farm's exact acreage, current monthly water consumed vs. quota limit, live soil moisture data, and a 3-day local weather forecast.
2. **Provider Cascade**: It feeds all this data to ultra-fast **Groq (openai/gpt-oss-120b)**. 
3. **Resiliency Built-in**: If Groq is rate-limited or unavailable, the system silently and automatically cascades down through 8 different fallback models via **OpenRouter**.
4. **Offline Rule-Based Guarantee**: If the internet drops or all AI providers are down, it uses a strict offline mathematical formula (FAO-56). 
5. **No Failures**: You will *always* receive a valid, formatted plan on the frontend. The system handles all AI unreliability for you.

## ⏱️ Expected Latency / TTL
Because we are utilizing a multi-provider AI cascade, the response time can vary based on which layer succeeds:
- **Optimal (Groq)**: `~3.5 to 5 seconds` (Expected ~90% of the time)
- **Degraded (OpenRouter Fallback)**: `10 to 45 seconds` (Will take longer if it has to try 3-4 different free models before one succeeds).
- **Offline Fallback**: `< 1 second`

*UI Tip: Ensure your loading button says "Generating AI Plan..." and is not blocked by short timeouts. It is safe to allow the mutation to load for up to 60 seconds.*

## 🤖 Can I Display the AI's "Reasoning"?
**Yes!** Every single AI plan is structurally forced to return an agronomic chain-of-thought in 2-3 sentences so the farmer knows *why* the AI chose this schedule.

You can access this and show it beautifully in the UI as follows:
```tsx
const reasoning = latestPlan.plan.reasoning;
// Example: "Based on the 32°C forecast and the wheat entering the flowering stage, priority water has been given to Zone A to prevent yield loss."
```

## 🛠️ Usage Options & Examples

The `api.irrigation` tRPC router provides 3 procedures. All routes enforce farm-level security matching (Only the Owner or Assigned Farmer can execute them).

### 1. `requestPlan` (useMutation)
Triggers the backend pipeline to generate today's fresh plan.

```tsx
import { api } from "~/utils/api";

export function GeneratePlanButton({ farmId }: { farmId: string }) {
  const utils = api.useUtils();
  
  const generatePlan = api.irrigation.requestPlan.useMutation({
    onSuccess: (data) => {
      // The AI completed successfully!
      // Invalidate queries to refresh the UI immediately
      utils.irrigation.getLatestPlan.invalidate({ farmId });
    },
    onError: (error) => {
      console.error(error.message); // Will only error on auth or missing farm
    }
  });

  return (
    <button 
      onClick={() => generatePlan.mutate({ farmId })}
      disabled={generatePlan.isPending}
    >
      {generatePlan.isPending ? "Generating via AI..." : "Generate Today's Plan"}
    </button>
  );
}
```

### 2. `getLatestPlan` (useQuery)
Used on the main dashboard to grab the active plan generated today.

```tsx
import { api } from "~/utils/api";

export function ActivePlanCard({ farmId }: { farmId: string }) {
  const { data: latestPlan, isLoading } = api.irrigation.getLatestPlan.useQuery({ farmId });

  if (isLoading) return <div>Loading...</div>;
  if (!latestPlan) return <div>No plan generated for today yet.</div>;

  return (
    <div className="card">
      <h3>Today's Schedule</h3>
      
      {/* 🛑 Catch quota limits here */}
      {latestPlan.plan.quotaWarning && (
        <div className="text-red-500 font-bold">
          Warning: The AI requested more water than your monthly quota allows. The schedule has been proportionally scaled down.
        </div>
      )}

      {/* Show the Reasoning */}
      <div className="bg-blue-50 p-4 italic">
        "🤖 {latestPlan.plan.reasoning}"
      </div>
      
      {/* Loop the Zones */}
      <ul>
        {latestPlan.plan.zones.map((zone) => (
          <li key={zone.zoneId}>
             {zone.scheduledAt} — {zone.cropType}: {(zone.recommendedLitres / 1000).toFixed(2)} m³
          </li>
        ))}
      </ul>
      <p className="text-xs text-gray-500">
        Generated by: {latestPlan.modelUsed}
      </p>
    </div>
  );
}
```

### 3. `listPlans` (useQuery)
Used for history, logs, or auditing. Supports infinite scrolling or table pagination.

```tsx
const { data: history } = api.irrigation.listPlans.useQuery({ 
  farmId, 
  limit: 10,
  offset: 0
});

// Returns an array of historical plans you can map over.
```

## 🏗️ The `IrrigationPlan` Data Structure

Whenever you interact with a `.plan` property from the endpoints above, it conforms strictly to the following auto-inferred typescript shape.

```typescript
type IrrigationPlan = {
  reasoning: string; 
  totalLitres: number; 
  quotaWarning: boolean; 
  
  zones: Array<{
    zoneId: string;
    cropType: string;
    growthStage: string;
    recommendedLitres: number; // Volume required
    scheduledAt: string; // "HH:MM" (e.g. "05:30")
    confidence: "HIGH" | "MEDIUM" | "LOW";
    notes?: string; 
  }>;
};
```
